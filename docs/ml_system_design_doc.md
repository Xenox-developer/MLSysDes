# ML System Design Document — Predictive Maintenance

## 1. Цель проекта
Разработать систему предиктивного обслуживания, которая на основе исторических сенсорных данных предсказывает вероятность внеплановой остановки или появления аномалий в работе оборудования. Результат — раннее предупреждение для планирования техобслуживания.

## 2. Бизнес-требования и ограничения
### Требования:
- Заблаговременное обнаружение потенциальных сбоев.  
- Низкий процент ложноположительных срабатываний (precision важен).  
- Регулярное переобучение (работа с новой порцией данных).

### Ограничения:
- Конфиденциальность и доступность данных.  
- Ограниченные вычислительные ресурсы (модель должна быть компактной).  
- Частота обновления данных: возможно, 1 час/сутки.

## 3. Скоуп (что входит / не входит)
### Входит:
- Подготовка данных и ресемплирование.
- Формирование признаков (статистики, PCA).
- Обучение LSTM/autoencoder и байес-модели.
- Pipeline инференса (скрипт/ноутбук).

### Не входит:
- Продукционный деплой (API в Kubernetes).
- Полный мониторинг drift/telemetry (планируем в будущем).
- Реальные интеграции с ticketing/alerting.

## 4. Предпосылки
- Есть исторические данные сенсоров.
- Наличие альтернативного решения от соседней команды, требуется провести сравнение различных подходов.

## 5. Постановка задачи
- Формулировка: anomaly detection / forecasting сбоя.
- Входы: временные ряды сенсоров, метаданные (id оборудования, timestamp).
- Выход: score аномалии и бинарный триггер (threshold).
- Метрики: ROC-AUC, Precision@k, Recall, F1 для событий; бизнес: уменьшение downtime.

## 6. Архитектура решения (блок-схема)
